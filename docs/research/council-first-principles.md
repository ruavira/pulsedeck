FIRST PRINCIPLES VIEW

Strip it down. A live interactive presentation is exactly one loop: presenter shows a prompt → N phones submit → aggregate renders on the big screen fast enough to feel alive. Everything else — themes, avatars, lobby music, 26 question types, LMS sync, SKU ladders — is decoration on that loop. The loop's irreducible physics: state fan-out (1→300 slide sync), ingest fan-in (300→1 answers), and aggregation latency under ~1–2 seconds. That's it.

(1) Critiques. All four platforms violate first principles the same way: they monetize the loop itself (participant caps, question caps) — Mentimeter's 50/month lockout, Kahoot's 10-player free tier, Wooclap's "5 active questions" are rent extracted from the core physics, which is why users churn. Kahoot's 20+ question types across four vendors reduce to ~4 primitives: choose-from-set (MCQ/poll/T-F/image-choice/ranking/scale are all this), free-text (word cloud/open-ended/Q&A), place-a-point (pin/slider/2x2), and order-a-set. Wooclap's 26 types are combinatorial noise over these primitives. Static-image slide import (all four!) proves import is a rendering problem they never solved — they rasterize because faithful re-layout is hard; that's an honest trade, not a flaw. Kahoot's speed-scoring is anti-physics: it converts network jitter into unfairness (they admitted it by shipping Accuracy mode a decade late). Mentimeter's real moat is boring: Ably, after their homegrown layer died at 35k connections — the only first-principles investment any of them made.

(2) MUST DO: Build the loop on 3 tables (session, slide_state, responses) with Supabase Realtime broadcast for slide sync and plain INSERTs for answers — aggregate server-side (Postgres count/tally via a single subscription on aggregates, NOT 300 clients subscribing to raw responses; that's the death mode at 300×N rows). Implement the 4 primitives well; skin them as 10+ "types" in UI. Presenter state must be recoverable: refresh the presenter tab and resume exactly — single-operator constraint makes crash-recovery THE feature. Client auto-reconnect with state resync (AhaSlides shipped this as an apology). Rasterize PPT/PDF to images and don't apologize — it's what everyone does; markdown import is where you can be natively better. Score by correctness, timer as ceiling only. QR + short code + anonymous-by-default join, zero accounts, sub-5-second join. MUST AVOID: per-participant WebSocket fan-out of raw responses; client-side aggregation; word-cloud re-layout on every submission (batch at 500ms ticks); AI in the live path (AI is authoring-time only — correct instinct); any feature requiring a second operator; character limits that force Kahoot-style truncated questions.

(3) Trade-offs I accept: static slide imports (fidelity < reliability); polling-fallback latency of 1–2s over WebSocket purity; 4 primitives over 26 types; ugly-but-recoverable over animated-but-fragile; leaderboard ties broken by submission timestamp, not speed points.
